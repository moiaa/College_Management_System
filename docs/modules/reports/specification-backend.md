# Техническое задание: Backend модуля «Отчёты» (Reports)

## 1. Назначение модуля

Модуль «Отчёты» предоставляет REST API для генерации сводных таблиц и статистики колледжа: успеваемость студентов, посещаемость занятий, общие показатели. Отчёты используются администрацией для аналитики, преподавателями — для контроля групп, студентами — для просмотра своей статистики.

Backend отвечает за приём запросов с фильтрами, агрегацию данных из других модулей (Gradebook, Admin Panel), генерацию файлов (PDF/Excel) и их хранение.

Доступ: `admin` — все отчёты, `teacher` — отчёты по своим группам и дисциплинам, `student` — только личная статистика.

## 2. Функциональные требования

### 2.1. Основные функции

- **Генерация отчётов по успеваемости:** сводная таблица оценок по группе за период, средний балл по предмету, рейтинг студентов, динамика успеваемости.
- **Генерация отчётов по посещаемости:** табель посещаемости, процент пропусков, статистика уважительных/неуважительных пропусков.
- **Общая статистика:** количество студентов по группам, средний балл по колледжу, топ-10 студентов.
- **Управление отчётами:** просмотр списка своих отчётов, повторная генерация, удаление старых.
- **Экспорт в PDF/Excel:** генерация файла в указанном формате.
- **Асинхронная генерация:** большие отчёты ставятся в очередь, пользователь получает `job_id` и проверяет статус.

### 2.2. Пользовательские сценарии

**Сценарий 1: Преподаватель генерирует табель успеваемости группы**

1. Преподаватель выбирает тип "Успеваемость", указывает группу (ИС-31) и период (01.09.2026 — 30.09.2026).
2. Backend проверяет права (преподаватель ведёт дисциплину в этой группе), валидирует параметры.
3. Если данных < 100 записей — генерирует сразу, возвращает ссылку на скачивание. Если больше — ставит в очередь, возвращает `report_id` и статус `generating`.
4. Преподаватель скачивает PDF с таблицей оценок.

**Сценарий 2: Куратор скачивает табель посещаемости**

1. Куратор выбирает "Посещаемость", указывает группу и месяц.
2. Backend агрегирует данные из `attendance` (Gradebook), считает проценты пропусков.
3. Формирует PDF с таблицей посещаемости, сохраняет в `storage/reports/`.
4. Куратор скачивает файл из списка своих отчётов.

**Сценарий 3: Администратор смотрит общую статистику**

1. Администратор запрашивает "Общая статистика" без фильтров.
2. Backend возвращает JSON: количество студентов, групп, средний балл, топ-10 студентов.
3. Данные используются для дашборда админ-панели.

**Сценарий 4: Повторная генерация отчёта**

1. Пользователь находит старый отчёт и нажимает "Сгенерировать заново".
2. Backend создаёт новый отчёт с актуальными данными.
3. Старый остаётся в истории, новый появляется вверху списка.

## 3. Нефункциональные требования

- **Производительность:** синхронная генерация (< 100 записей) — не более 2 секунд. Асинхронная (> 100 записей) — постановка в очередь за 0.5 секунды. Скачивание файла — не более 1 секунды.
- **Безопасность:** все эндпоинты требуют авторизации. Преподаватель видит только свои группы, студент — только свою статистику. Проверка прав через `core/`.
- **Совместимость:** модуль использует `core/` (БД, аутентификация, конфигурация). Читает данные из Gradebook (`grades`, `attendance`) и Admin Panel (`student_groups`, `subjects`, `users`). Код соответствует PEP 8, тесты через `pytest`.
- **Формат данных:** JSON (UTF-8), даты — ISO 8601 (`2026-09-18`). Файлы — PDF (`reportlab`), Excel (`openpyxl`).
- **Хранилище:** локальная папка `storage/reports/` или S3 (настраивается через `.env`).

## 4. Интерфейсы

### 4.1. API Endpoints

Согласовано с frontend-командой (issue #22).

**Общие правила:**
- Префикс: `/api/v1/reports`
- Авторизация: `Authorization: Bearer <token>`
- Ошибки: `{"detail": "Текст ошибки"}`, код `422` — стандартный FastAPI
- Списки: `{"items": [...], "total": 42, "page": 1, "page_size": 20}`
- Query-пагинация: `page` (1), `page_size` (20, макс. 100)

**Сводная таблица**

| Метод  | Endpoint                            | Описание                     | Успешный ответ | Ошибки        |
| ------ | ----------------------------------- | ---------------------------- | -------------- | ------------- |
| GET    | `/api/v1/reports`                   | Список отчётов пользователя  | 200            | 422           |
| GET    | `/api/v1/reports/{report_id}`       | Детали одного отчёта         | 200            | 404, 403      |
| POST   | `/api/v1/reports/generate`          | Запуск генерации             | 202            | 403, 422      |
| GET    | `/api/v1/reports/{report_id}/status`| Статус генерации             | 200            | 404           |
| GET    | `/api/v1/reports/{report_id}/download` | Скачивание файла          | 200            | 404, 422      |
| DELETE | `/api/v1/reports/{report_id}`       | Удаление отчёта              | 204            | 404, 403      |
| GET    | `/api/v1/reports/statistics/summary`| Общая статистика (admin)     | 200            | 403           |

#### Отчёты

**Объект отчёта:**

```json
{
  "id": 15,
  "type": "performance",
  "status": "ready",
  "filters": {
    "group_id": 2,
    "subject_id": 7,
    "from": "2026-09-01",
    "to": "2026-09-30"
  },
  "file_path": "storage/reports/report_15.pdf",
  "file_format": "pdf",
  "created_by": 5,
  "created_at": "2026-09-18T10:00:00",
  "completed_at": "2026-09-18T10:00:05"
}
```

Типы: `performance` (успеваемость), `attendance` (посещаемость), `summary` (общая статистика).

Статусы: `pending` (в очереди), `generating` (генерируется), `ready` (готов), `failed` (ошибка).

##### `GET /api/v1/reports`

**Назначение:** страница списка отчётов текущего пользователя.

**Query-параметры (необязательные):**

| Параметр    | Тип    | Описание                                              |
| ----------- | ------ | ----------------------------------------------------- |
| `type`      | строка | Фильтр: `performance`, `attendance`, `summary`        |
| `status`    | строка | Фильтр: `pending`, `generating`, `ready`, `failed`    |
| `group_id`  | число  | Фильтр по группе                                      |
| `page`, `page_size` | число | Пагинация                                    |

**Успешный ответ — `200 OK`:**

```json
{
  "items": [
    {
      "id": 15,
      "type": "performance",
      "status": "ready",
      "filters": {"group_id": 2, "from": "2026-09-01", "to": "2026-09-30"},
      "file_format": "pdf",
      "created_by": 5,
      "created_at": "2026-09-18T10:00:00",
      "completed_at": "2026-09-18T10:00:05"
    }
  ],
  "total": 1,
  "page": 1,
  "page_size": 20
}
```

**Ошибки:** `422` — некорректное значение параметра.

##### `GET /api/v1/reports/{report_id}`

**Параметры пути:** `report_id` (целое число).

**Успешный ответ — `200 OK`:** объект отчёта.

**Ошибки:**
- `404 Not Found` — `{"detail": "Отчёт не найден"}`
- `403 Forbidden` — отчёт принадлежит другому пользователю

##### `POST /api/v1/reports/generate`

**Назначение:** запуск генерации нового отчёта.

**Тело запроса:**

```json
{
  "type": "performance",
  "format": "pdf",
  "filters": {
    "group_id": 2,
    "subject_id": 7,
    "from": "2026-09-01",
    "to": "2026-09-30"
  }
}
```

| Поле      | Тип    | Обязательно | Описание                                          |
| --------- | ------ | ----------- | ------------------------------------------------- |
| `type`    | строка | да          | `performance`, `attendance` или `summary`         |
| `format`  | строка | нет         | `pdf` или `excel` (по умолчанию `pdf`)            |
| `filters` | объект | да          | Параметры фильтрации (зависят от типа отчёта)     |

**Фильтры для `performance`:** `group_id` (обязательно для преподавателя), `subject_id` (необязательно), `from`, `to` (формат `YYYY-MM-DD`).

**Фильтры для `attendance`:** `group_id` (обязательно), `from`, `to`.

**Фильтры для `summary`:** не требуются (только для `admin`).

**Успешный ответ — `202 Accepted`:**

```json
{
  "report_id": 15,
  "status": "generating",
  "message": "Отчёт генерируется. Проверьте статус через несколько секунд."
}
```

Если отчёт маленький, статус может быть сразу `ready`.

**Ошибки:**
- `403 Forbidden` — нет прав на этот тип отчёта
- `422 Unprocessable Entity` — некорректные фильтры (несуществующая группа, `from` позже `to`)

##### `GET /api/v1/reports/{report_id}/status`

**Назначение:** проверка статуса генерации (для асинхронных отчётов).

**Успешный ответ — `200 OK`:**

```json
{
  "report_id": 15,
  "status": "generating",
  "progress": 65
}
```

Поле `progress` — процент выполнения (0–100), только для статуса `generating`.

**Ошибки:** `404` — отчёт не найден.

##### `GET /api/v1/reports/{report_id}/download`

**Назначение:** скачивание готового файла.

**Успешный ответ — `200 OK`:** бинарный файл с заголовками:
- `Content-Type: application/pdf` или `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`
- `Content-Disposition: attachment; filename="report_15.pdf"`

**Ошибки:**
- `404` — отчёт не найден
- `422` — отчёт ещё не готов (`status != "ready"`)

##### `DELETE /api/v1/reports/{report_id}`

**Назначение:** удаление отчёта из списка (файл тоже удаляется).

**Успешный ответ — `204 No Content`** (тела нет).

**Ошибки:** `404` — отчёт не найден; `403` — отчёт чужой.

#### Общая статистика

##### `GET /api/v1/reports/statistics/summary`

**Назначение:** агрегированная статистика по колледжу (только `admin`).

**Параметры:** нет.

**Успешный ответ — `200 OK`:**

```json
{
  "students_total": 450,
  "groups_total": 18,
  "teachers_total": 45,
  "subjects_total": 120,
  "average_gpa": 4.2,
  "top_students": [
    {"id": 12, "full_name": "Иванов Иван", "gpa": 4.9},
    {"id": 34, "full_name": "Петрова Анна", "gpa": 4.8}
  ],
  "attendance_rate": 0.87
}
```

**Ошибки:** `403` — роль не `admin`.

### 4.2. Взаимодействие с другими модулями

- **core/ (ядро):** подключение к БД, аутентификация, проверка ролей. Модуль использует и не дублирует.
- **Gradebook:** читает `grades` (оценки) и `attendance` (посещаемость) для генерации отчётов.
- **Admin Panel:** читает `student_groups`, `subjects`, `users` для фильтров и проверки прав.
- **Student Portal, Teacher Portal:** используют API для отображения статистики в личных кабинетах.
- **Reports — Frontend (issue #22):** потребитель всех эндпоинтов раздела 4.1.

## 5. Структура базы данных

### 5.1. Таблицы

**Таблица:** `reports` (создаётся модулем Reports)

| Поле          | Тип      | Описание                                              |
| ------------- | -------- | ----------------------------------------------------- |
| id            | Integer  | Первичный ключ                                        |
| type          | String   | Тип отчёта: `performance`, `attendance`, `summary`   |
| status        | String   | Статус: `pending`, `generating`, `ready`, `failed`   |
| filters       | JSON     | Параметры фильтрации (JSON-объект)                    |
| file_format   | String   | Формат файла: `pdf`, `excel`                          |
| file_path     | String   | Путь к файлу (`storage/reports/report_15.pdf`)        |
| error_message | String   | Текст ошибки, если `status = "failed"`                |
| created_by    | Integer  | Внешний ключ на `users.id`                            |
| created_at    | DateTime | Время создания запроса                                |
| started_at    | DateTime | Время начала генерации                                |
| completed_at  | DateTime | Время завершения генерации                            |

**Таблицы из других модулей (читаются):**

- `users` (core/) — данные пользователей для проверки прав.
- `student_groups` (admin_panel/) — справочник групп для фильтров.
- `subjects` (admin_panel/) — справочник дисциплин для фильтров.
- `grades` (gradebook/) — оценки для отчётов по успеваемости.
- `attendance` (gradebook/) — посещаемость для отчётов по пропускам.
