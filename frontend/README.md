# Фронтенд

Обычный HTML/CSS/JS, без сборки и без фреймворка. У каждого модуля — своя
папка: `frontend/<модуль>/`, обычно с `index.html` внутри (плюс свои
`.css`/`.js` файлы рядом, как удобно команде).

## Как это раздаётся

`core/api.py` монтирует всю папку `frontend/` как статику через
`app.mount("/frontend", StaticFiles(...), html=True)`. Значит, после

```bash
python main.py init
python main.py run
```

страница вашего модуля открывается по адресу вида:

```
http://127.0.0.1:8000/frontend/<модуль>/
```

(благодаря `html=True` не нужно дописывать `index.html` в конце — оно
подхватится само).

## Как обращаться к API

Так как страница и API открываются с одного и того же адреса
(`http://127.0.0.1:8000`), можно просто делать `fetch()` с
относительным путём — браузер не будет блокировать запрос как
кросс-доменный:

```js
const response = await fetch("/api/v1/<модуль>/...");
const data = await response.json();
```

CORS в `core/api.py` тоже включён (на случай, если вы всё же откроете
`index.html` напрямую как файл или через отдельный dev-сервер), но при
запуске через `python main.py run` он вам не понадобится.

## Рабочий пример

`frontend/_example/` — не один из 7 модулей, а рабочий образец: страница
на чистом JS, которая ходит в `/api/v1/example/items` (тот же
демонстрационный backend-эндпоинт, что и в
`docs/examples/example_module/`). Откройте
`http://127.0.0.1:8000/frontend/_example/` после `python main.py run` и
посмотрите исходник `index.html` — оттуда можно скопировать структуру
`fetch()`-запросов (GET списка, POST создания, обработка ошибок) для
своей страницы.
